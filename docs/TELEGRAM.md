# Тексты для Telegram

Готовые к вставке описания проекта. README — документация для разработчика;
здесь то же самое, но так, как это читают в канале: без таблиц, без заголовков
Markdown, с учётом лимитов Telegram.

Главное требование к этим текстам — не обещать больше, чем проверено.
Работоспособность моста подтверждается тестом на двух физических телефонах
(раздел 11 ТЗ), и он ещё не проводился. Во всех вариантах ниже это сказано
прямо. Если будете править — сохраняйте это.

## 1. Описание канала / бота (лимит 255 символов)

```
DualStream Uniter — два Android-телефона делят одну Bluetooth-гарнитуру.
Телефон B отдаёт звук телефону A по Bluetooth RFCOMM, A микширует и играет
оба источника в наушниках. Без Wi-Fi, интернета, root и сервера. Multipoint
не нужен. Открытый код.
```

## 2. Короткая строка для bio (лимит 70 символов)

Одна Bluetooth-гарнитура на два Android-телефона. Без Wi-Fi и root.

## 3. Пост-анонс

```
🎧 DualStream Uniter 2.1

Два Android-телефона и одна Bluetooth-гарнитура. Оба звука слышны
одновременно, в одних наушниках.

Как это работает

Телефон A — основной. К нему подключена гарнитура. Он держит
RFCOMM-сервер, декодирует поток от второго телефона, смешивает его со
своим источником и отдаёт результат в наушники по A2DP.

Телефон B — дополнительный. Захватывает свой звук или свой микрофон,
кодирует в Opus и отправляет телефону A по Bluetooth Classic RFCOMM.

Bluetooth используется на обоих участках. Ни Wi-Fi, ни интернета, ни
UDP, ни Wi-Fi Direct, ни локального сервера, ни root. Приложение вообще
не объявляет разрешение INTERNET — это не обещание, а свойство сборки,
и оно проверяется автоматически на каждом коммите.

Гарнитуре не нужен Bluetooth Multipoint: она соединена только с
телефоном A.

Четыре режима вывода

• Hard Split — левое ухо свой источник, правое второй телефон
• Mixed Stereo — оба источника в оба уха
• Remote Only — телефон A работает чистым приёмником
• Priority — свой звук автоматически приглушается, когда говорит второй
  телефон

Два микрофона

Каждый телефон может отдавать свой встроенный микрофон, и в Hard Split
это даёт по микрофону на ухо.

Запись намеренно жёстко привязана к встроенному микрофону, а маршрут
проверяется уже после старта записи. Если отдать выбор Android, он
может увести вход на микрофон гарнитуры — а это переводит её в
hands-free и обрывает A2DP. Плюс микрофон гарнитуры принадлежит только
одному телефону: второй, кто его попросит, останется без входа.
Привязка каждого телефона к своему железу — это и есть то, что
позволяет писать с двух сразу.

Отдельно: заглушённый системой рекордер продолжает отдавать кадры по
расписанию, просто нулевые. Приложение это отслеживает и показывает
«заглушено», а не «всё хорошо, просто тихо».

Чего приложение не умеет, и почему

• Системный захват доступен не для всех приложений. Многие стриминговые
  сервисы его запрещают, а звонки и DRM-звук не захватываются никогда.
  Когда поток идёт, но он цифровая тишина — так и написано. Тишина не
  выдаётся за рабочий поток.
• Hard Split работает по источнику, которым владеет само приложение. Без
  системных привилегий перехватить чужой звук на телефоне A и
  принудительно развести его по каналам нельзя.
• Opus-энкодер есть не на всех устройствах — он обязателен только с
  Android 10. Если его нет, приложение честно сообщает и переходит на
  ADPCM.
• Задержка не обещается. Пока она не измерена на реальной паре
  телефонов, цифры называть нечего.

Состояние

Сборка зелёная: 85 юнит-тестов, APK собирается, приложение запускается
на эмуляторе, пакет проверяется на отсутствие сетевых разрешений.

Но зелёная сборка — это не работающий мост. Два Bluetooth-канала на
одной антенне, сосуществование A2DP и RFCOMM, борьба за микрофон,
сквозная задержка — ничего из этого раннер проверить не может. Тест на
двух физических телефонах ещё не проводился. Процедура лежит в
репозитории.

Исходники: https://github.com/terminaldetector/Dualstream

Android 10+ (нужен для системного захвата звука)
```

## 4. Короткий пост, если нужен без подробностей

```
🎧 DualStream Uniter

Два Android-телефона делят одну Bluetooth-гарнитуру, и оба звука слышны
одновременно.

Телефон B кодирует свой звук или микрофон в Opus и отдаёт телефону A по
Bluetooth Classic RFCOMM. Телефон A декодирует, микширует со своим
источником и играет в наушники по A2DP.

Без Wi-Fi, интернета, UDP, сервера и root — приложение даже не объявляет
разрешение INTERNET. Гарнитуре не нужен Multipoint.

Четыре режима: по источнику на ухо, оба в оба, только удалённый, и
автоприглушение своего звука под чужой. Каждый телефон может отдавать
свой встроенный микрофон — в режиме «по уху» это даёт по микрофону на
ухо.

Сборка зелёная, но на двух реальных телефонах мост пока не проверялся.
Это следующий шаг, и без него говорить, что он работает, нельзя.

https://github.com/terminaldetector/Dualstream
```
